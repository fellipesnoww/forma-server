# 5.6 Reports de exercícios

> Roadmap: [roadmap-backend.md](../roadmap-backend.md) › Fase 5 › 5.6 Reports de exercícios
> Data: 2026-10-07
>
> Qualquer usuário reporta um problema nos dados de um exercício do catálogo (nome, grupo
> muscular, imagem/vídeo errado...) com um texto livre. Só o painel admin lê os reports.

## Escopo entregue

- [x] Tabela `exercise_reports` (referência ao exercício + texto)
- [x] `POST /exercises/:id/reports` em `features/exercises/` — qualquer usuário autenticado
- [x] `features/admin/exercise-reports/` — `GET /admin/exercise-reports` (admin e super_user), paginado com filtros
- [x] Documentação OpenAPI (envio na tag `Exercicios`; leitura na tag `Admin`)
- [x] Testes automatizados — `test/exercise-reports.test.ts` (11 casos)

## Decisões técnicas

- **Só exercícios do catálogo.** O report serve para o admin corrigir o catálogo global; exercício custom é do próprio usuário, que já pode editá-lo. Id custom ou inexistente responde 404 (mesma mensagem, sem vazar existência). Exercício **desativado** aceita report: o usuário ainda o vê em planilhas e sessões antigas.
- **Envio dentro de `features/exercises/`**, como sub-recurso (`/exercises/:id/reports`): reaproveita `findCatalogExerciseById` e o param `:id` já validado como uuid. A leitura segue o padrão de ratings: pacote próprio em `features/admin/exercise-reports/`, registrado no escopo de `/admin`, herdando `authenticate` + `requireRole('admin')` (admin e super_user leem, user recebe 403). A matriz de `test/admin-access.test.ts` cobre a rota automaticamente.
- **Qualquer papel pode reportar**: a rota usa só `authenticate`.
- **`text` obrigatório**, trim + 1–2000 caracteres (`VARCHAR(2000)`). Sem categoria/enum de motivo por enquanto: texto livre basta para o volume esperado.
- **`created_at` definido pelo servidor.** Vários reports por usuário e por exercício, sem edição, remoção nem status de "resolvido" (ver pendências).
- **Ordenação `created_at desc, id desc`**: `id` desempata reports do mesmo milissegundo (paginação estável).
- **Item admin traz o exercício resolvido** (`{ id, name, isActive }`) e o autor (`{ id, email, displayName }`), para o painel não precisar de uma segunda chamada.
- **Cascade em `user_id` e `exercise_id`**: apagar a conta apaga os reports dela; exercícios do catálogo não são apagados pela API (só desativados), então o cascade do exercício só age via banco.
- **Sem audit log**: a rota admin é só leitura.

## APIs

| Método | Rota                      | Descrição                                                                          |
| ------ | ------------------------- | ---------------------------------------------------------------------------------- |
| POST   | `/exercises/:id/reports`  | `{ text }` → 201 `{ id, exerciseId, text, createdAt }`; 404 se não for do catálogo |
| GET    | `/admin/exercise-reports` | `?page&limit&exerciseId&userId&from&to` → `{ items, total, page, limit }`          |

Item da listagem admin: `{ id, exercise: { id, name, isActive }, user: { id, email, displayName }, text, createdAt }`.
`from`/`to` são ISO 8601 com offset e inclusivos, filtrando `createdAt`.

## Modelo de dados

- **`exercise_reports`**: `id`, `user_id` (FK `users`, cascade), `exercise_id` (FK `exercises`, cascade), `text` (`VARCHAR(2000)`), `created_at` (`TIMESTAMPTZ(3)`, default `now()`). Índices `(created_at)` para a listagem geral e `(exercise_id, created_at)` para o filtro por exercício.

## Variáveis de ambiente

Nenhuma nova.

## Como testar

```bash
curl -s -X POST localhost:3333/exercises/<exercise-id>/reports -H "authorization: Bearer $ACCESS" \
  -H 'content-type: application/json' -d '{"text":"O vídeo mostra o supino inclinado, não o reto"}'
# Com token de admin/super_user:
curl -s "localhost:3333/admin/exercise-reports?exerciseId=<exercise-id>" -H "authorization: Bearer $ADMIN"
```

Automatizado (`test/exercise-reports.test.ts`): criação com data do servidor, texto com trim e dono
correto; admin e super_user também reportam; exercício custom e inexistente → 404; texto ausente,
vazio e longo → 400; id não-uuid → 400; sem token → 401. Listagem: 403 para user, 401 sem token,
admin e super_user leem, mais recente primeiro com exercício e autor, filtros por exercício e
período, paginação mantendo o total.

## Pendências

- Botão "reportar problema" no app/web e a tela de reports no painel (_cliente_).
- Sem status de triagem (aberto/resolvido) nem resposta ao usuário; entra se o volume pedir.
- Sem categoria de motivo (nome, mídia, grupo muscular); hoje é só texto livre.
