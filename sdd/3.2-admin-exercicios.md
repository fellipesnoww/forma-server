## Decisões técnicas

- **O painel é o único escritor HTTP do catálogo global.** `features/exercises/` continua só lendo `exercises`/`muscle_groups` (e escrevendo exercícios custom); a escrita do catálogo vive em `features/admin/exercises/admin-exercises.repository.ts`. O seed é o outro escritor.
- **Mídia no corpo do cadastro**, no mesmo formato de `POST /media` (`{ data, mimeType, filename? }`), com `bodyLimit = MEDIA_BODY_LIMIT` na rota. O upload usa `dbMediaStorage` com `ownerId: null` (`admin.media.ts`) e roda **antes** da transação do audit log — se a mutação falhar depois, sobra um asset órfão (mesmo descope das fotos de sessão/atividade).
- **`GET /media/:id` passou a liberar mídia sem dono** para qualquer usuário autenticado: imagens do catálogo e ícones de conquistas precisam aparecer no app. Mídia com dono segue a regra anterior (dono ou admin; demais → 404).
- **Nome único sem diferenciar maiúsculas** (409), checado no service dentro da transação; o `@@unique([name])` do banco (exato) segue como rede de segurança. Renomear para o próprio nome é permitido.
- **`muscleGroupSlug: null`** remove o grupo; **`mediaUrl: null`** remove a mídia; mandar `media` e `mediaUrl: null` juntos → 400.
- **Variante feminina da mídia** (`female_media_url`, migration `20261007120000_add_exercise_female_media_url`): `femaleMedia` sobe a versão com executora feminina, independente de `media` (que segue como padrão/masculina). Mesmas regras: `femaleMediaUrl: null` remove; `femaleMedia` + `femaleMediaUrl: null` juntos → 400. `GET /exercises` e as respostas do admin expõem `femaleMediaUrl` (null em exercícios custom); o plugin `media-urls` assina o campo no driver s3 e `media:migrate-s3` também migra a coluna.
- **Desativar** tira o exercício de `GET /exercises` e de novas referências (`exerciseReferenceExists` já exigia `isActive`); planilhas e sessões existentes continuam apontando para ele. Repetir o status atual é no-op sem audit log.
- **Grupos musculares sem paginação** (`{ items }`): catálogo pequeno (12 no seed) usado em selects do painel; cada item traz `exerciseCount` (ativos + inativos).
- **Slug derivado do nome** quando omitido (`Glúteo Médio` → `gluteo-medio`, NFD sem diacríticos). Slug explícito precisa casar `^[a-z0-9]+(-[a-z0-9]+)*$`. Nome (case-insensitive) e slug únicos → 409. Trocar o slug é permitido, com aviso no OpenAPI: clients usam o slug em `?muscleGroup=` e `muscleGroupSlug`.
- **Sem rate limit estrito** nas rotas com upload admin: só admins autenticados chegam ali e o limite global continua valendo; o limite de 10/min de upload atrapalharia o cadastro em lote do catálogo.

## APIs

| Método | Rota                          | Descrição                                                                                         |
| ------ | ----------------------------- | ------------------------------------------------------------------------------------------------- |
| GET    | `/admin/exercises`            | Paginado; `?q=&muscleGroup=&status=active\|inactive\|all&page=&limit=`                            |
| POST   | `/admin/exercises`            | `{ name, muscleGroupSlug?, isActive?, media?, femaleMedia? }` → 201                               |
| PATCH  | `/admin/exercises/:id`        | `{ name?, muscleGroupSlug?\|null, media?, mediaUrl?: null, femaleMedia?, femaleMediaUrl?: null }` |
| PATCH  | `/admin/exercises/:id/status` | `{ isActive }`                                                                                    |
| GET    | `/admin/muscle-groups`        | Todos, com `exerciseCount`                                                                        |
| POST   | `/admin/muscle-groups`        | `{ name, slug? }` → 201                                                                           |
| PATCH  | `/admin/muscle-groups/:id`    | `{ name?, slug? }`                                                                                |

## Modelo de dados

Sem tabelas novas — usa `exercises` e `muscle_groups` da 1.3 (+ coluna `female_media_url` nullable em `exercises`). Mídia em `media_assets` com `owner_id` null.

## Variáveis de ambiente

Nenhuma nova (reusa `MEDIA_MAX_SIZE_MB` / `MEDIA_ALLOWED_MIME_TYPES`).

## Como testar

```bash
curl -s -X POST localhost:3333/admin/exercises -H "authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' \
  -d '{"name":"Supino com corrente","muscleGroupSlug":"peito","media":{"data":"<base64>","mimeType":"image/png"}}'
curl -s -X PATCH localhost:3333/admin/exercises/$ID/status -H "authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' -d '{"isActive":false}'
```

Automatizado (`test/admin-catalog.test.ts`, 22 casos): slug derivado e validado; 409 de nome/slug; contagem por grupo; mídia global legível por user; 409 de nome case-insensitive sem audit log; 400/415 de validação; filtros e paginação; antes/depois no audit log; remoção de grupo/mídia; desativação some do catálogo, bloqueia nova planilha e preserva a existente; no-op sem log.
