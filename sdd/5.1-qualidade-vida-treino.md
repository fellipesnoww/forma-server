## Decisões técnicas

- **`:id` do last-session aceita catálogo ou custom**: ids são UUID, então o servidor procura primeiro no catálogo e depois nos custom exercises do usuário — o client não precisa dizer a origem (diferente de `/progress/load`, que usa query string com dois nomes). Catálogo desativado e custom removido (soft delete) continuam aceitos para o histórico não sumir. Custom de outro usuário → **404** (não 403 como em `PATCH /exercises/custom/:id`): é leitura, e 404 não confirma a existência do recurso.
- **"Última sessão" = maior `performedAt`**, não a criada por último: um registro retroativo (2.3) criado hoje com data antiga não vira sugestão. Desempate por `createdAt`. Sessões não finalizadas (`completedAt` null) entram — registros retroativos nem sempre são completados — e o client usa `?excludeSessionId=` para ignorar a sessão em andamento. Ocorrências sem séries são ignoradas; se o exercício aparece duas vezes na mesma sessão, vale a primeira por `sortOrder`.
- **Sugestão = série mais pesada** (desempate: mais reps), sem progressão automática (+2,5 kg etc.): a regra de progressão é decisão de produto/treinador e cabe ao client a partir de `sets`. Todas as séries contam, não só `completed` — mesma regra da 2.4.
- **Sem histórico → 200 com `lastSession: null`** (e não 404): o exercício existe, só não tem passado; o client trata um único formato.
- **Duplicate copia fielmente**, sem revalidar referências: um exercício desativado ou custom removido depois da criação já está na original, e recusar a cópia surpreenderia mais. A validação volta a valer quando o usuário edita a cópia via `PATCH`.
- **Body do duplicate é opcional** (`name`). Padrão `"<nome> (copia)"`, cortando o nome original para caber nos 120 caracteres da coluna. O schema é `nullish` porque o Fastify entrega `null` num POST sem body.
- **`defaultRestSeconds`**: inteiro 0–3600, nullable, por exercício da planilha. Só alimenta o cronômetro do client — o servidor não registra descanso executado.

## APIs

| Método | Rota                            | Descrição                                                                                                                                                                                 |
| ------ | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/exercises/:id/last-session`   | `?excludeSessionId=` → `{ exerciseId, customExerciseId, name, lastSession: { sessionId, sheetId, sheetName, performedAt, completedAt, sets[], suggestion: { weightKg, reps } } \| null }` |
| POST   | `/workout-sheets/:id/duplicate` | Body opcional `{ name? }` → 201 com o detalhe da planilha nova                                                                                                                            |

`defaultRestSeconds` passa a existir no input (`POST`/`PATCH /workout-sheets`) e no output de todos os
detalhes de planilha (`exercises[].defaultRestSeconds`, `null` quando não definido).

## Como testar

```bash
curl -s "localhost:3333/exercises/$EXERCISE_ID/last-session" -H "authorization: Bearer $ACCESS"
curl -s "localhost:3333/exercises/$EXERCISE_ID/last-session?excludeSessionId=$SESSION_ID" -H "authorization: Bearer $ACCESS"
curl -s -X POST "localhost:3333/workout-sheets/$SHEET_ID/duplicate" -H "authorization: Bearer $ACCESS"
curl -s -X POST "localhost:3333/workout-sheets/$SHEET_ID/duplicate" -H "authorization: Bearer $ACCESS" \
  -H 'content-type: application/json' -d '{"name":"Hipertrofia v2"}'
```

Automatizado (`test/training-qol.test.ts`): last-session sem histórico; mais recente por `performedAt`
(retroativo criado depois não vence); séries ordenadas e sugestão com desempate; outros exercícios da
sessão ignorados; `excludeSessionId`; isolamento entre usuários; custom removido; custom alheio/inexistente
→ 404; ids inválidos → 400; sem token → 401. `defaultRestSeconds`: persistência, `null` por padrão, PATCH,
limites. Duplicate: estrutura idêntica (ordem de dias e exercícios, metas, descanso), ids novos e cópia
independente, listagem, nome customizado, limite de 120 caracteres, custom removido, planilha
removida/alheia/inexistente → 404, nome inválido → 400.
